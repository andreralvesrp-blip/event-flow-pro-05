
- Clicksign: only template documents create full contracts; signed plain-PDF documents create contracts with data_pending=true (PDF saved to the private contract-pdfs bucket on receipt because Clicksign links expire); AI output is stored only in contracts.suggested_data until a user confirms. Distrato/aditivo are detected by file/template name and never create contracts.
- New Supabase Edge Functions are blocked in this project; new server endpoints go in TanStack server routes under src/routes/api/public/* with shared logic in src/lib/*.server.ts. The existing lead-intake edge function is frozen — never edit it; the "orcamento_automatico" form flow uses /api/public/lead-intake-v2 instead.
- Form flows are versioned via forms.flow_version ('atual' | 'orcamento_automatico'); the public form page /f/$slug reads flow_version from the lead-intake-v2 GET config and picks the flow and POST endpoint accordingly. bs-orcamento-teste is a test form excluded from Marketing reports.
- Personal date pages use isolated date_* tables and token-verified public endpoints; token hashes are stored, never raw tokens, to keep availability/interaction flows independent of lead intake and messaging. Calendar credentials and read-only calls stay server-side; persisted event cache stores only timing/status and expires within 60 seconds.
- Personal date WhatsApp navigation is synchronous in the click handler using browser-safe URL generation; contact telemetry uses keepalive in the background so calendar or recording latency cannot block navigation. Date selections and queues remain server-validated before confirmation.
